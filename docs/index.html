The problem it solves

Your agent forgets your product every session

Without persistent context, every session starts with you re-explaining phase, roadmap, metrics, and blockers. Product Pilot writes it down once — in a file your agent can read when instructed or wired into your host workflow.

● Without Product Pilot

You brief the agent. Again.

We're optimizing trial conversion. D7 retention is the blocker. Don't touch billing this week…
Got it — remind me, what's the current retention number and the target?
28% now, target is 30%. I told you yesterday.

…and you repeat it tomorrow, and the day after.

✓ With Product Pilot

The agent orients itself.

Read PRODUCT_PILOT.md. Active milestone: Trial conversion optimization.
Top blocker: D7 retention 28% vs 30% target. Billing is out of scope this week.
I'll focus changes on the activation flow. Anything new since last commit?

Zero re-briefing. It picked up exactly where you left off.

How it works

Modes that run without you

The skill detects the mode from what exists. Setup researches, Orient briefs, Pour refills the queue, Reconcile advances on evidence, Replan details the next milestone.

Orient — the same 20 lines reach every session through a hook and every dispatched task through its packet. When the queue is empty, Pour turns [unpoured] tasks into tickets.

pilot ›$ scripts/pilot-reconcile.sh --apply
edit ›Recent Shipped regenerated from git — 7 commits since 2026-10-01

Reconcile — evidence only: git for ships, a Check command for completion, ticket state for tasks. No "what changed?" question. Replan details the next milestone when the roadmap runs out.
Orchestration

Plug it into a fleet

Product Pilot slots into an agent orchestration system such as the Buzz desktop app, where a dispatcher persona builds queues and sends task packets to worker personas. Four wiring points, no new infrastructure.

1

Put the rule where packets copy from

Dispatchers paste each repo's "Read first" block into every task packet. The Pilot pointer lives inside that block, so a sandboxed worker that cannot read the repo still receives it.

2

Paste the banner into every packet

pilot-banner.sh prints about twenty lines: phase, release blockers, the ACTIVE milestone's open tasks, decisions past deadline, runway. The dispatcher runs it against the repo's current main and includes the output.

3

Pour before you sweep

Intake order: human-filed tickets, confirmed bugs, then [unpoured] tasks from the ACTIVE milestone poured into the tracker, then maintenance such as dependency bumps. The queue never starves while the roadmap has runway.

4

One Owner reconciles

Workers never edit the Pilot. The product-owner persona runs pilot-reconcile.sh --run-checks --apply after merges, ticks tasks whose tickets closed, and lands the edit by PR. Pre-commit and CI guard the structure.

What the worker never has to do: find the Pilot, decide whether a blocker applies to its task, or ask what the product is for. What the dispatcher never has to do: invent work when the tracker is empty. Wiring, hooks, and the Buzz observations are in references/AGENT_INSTRUCTION_REFERENCE.md.

Why it's different

Built to stay honest, not just look done

Product Pilot is opinionated about the failure modes of AI-assisted product work — drift, sycophancy, and fabricated data.

Observable phase triggers

Phase transitions fire on a deployment, a store status, or a Source command — never a date, and never a research deliverable. A gate stops a release, not the queue.

Anti-hallucination defaults

Never invents metric targets or competitor data — gaps are marked [TODO]. No [PLACEHOLDER] survives into final files.

"What's Blocking Ship"

A bulletized blockers section — one line per blocker with unblock condition, owner, and since-date. Prose is a structural defect.

Anti-sycophancy reviews

Pilot reviews lead with what's stale or below target — not what's done. A clean review means you didn't look hard enough.

Enforced by scripts, not promises

A SessionStart banner, a pre-commit guard, and a CI check carry the contract. TOOLING_GAPS.md lists what they still cannot reach.

Built for fleets

Dispatcher wiring: poured milestone tasks in the intake order, the banner in every packet, one Owner persona editing by PR, decisions with defaults and deadlines.

Give your AI coding agent product awareness.

Product Pilot bootstraps self-maintaining product docs for any project. Your agent learns what phase you're in, which milestone is active, and which metrics matter — so you stop repeating product context every single session.

The problem it solves

Your agent forgets your product every session

Without persistent context, every session starts with you re-explaining phase, roadmap, metrics, and blockers. Product Pilot writes it down once — in a file your agent reads on its own.

● Without Product Pilot

You brief the agent. Again.

We're optimizing trial conversion. D7 retention is the blocker. Don't touch billing this week…
Got it — remind me, what's the current retention number and the target?
28% now, target is 30%. I told you yesterday.

…and you repeat it tomorrow, and the day after.

✓ With Product Pilot

The agent orients itself.

Read PRODUCT_PILOT.md. Active milestone: Trial conversion optimization.
Top blocker: D7 retention 28% vs 30% target. Billing is out of scope this week.
I'll focus changes on the activation flow. Anything new since last commit?

Zero re-briefing. It picked up exactly where you left off.

Context — at session start the agent reads the Pilot and produces a tight orientation: current phase, active milestone, what's blocking ship, what shipped recently, and which metrics are at risk.

Update — when something ships or product state shifts, it asks what changed and edits only the relevant files, keeping the Pilot current without churn.

Why it's different

Built to stay honest, not just look done

Product Pilot is opinionated about the failure modes of AI-assisted product work — drift, sycophancy, and fabricated data.

Data-driven phase triggers

Phase transitions fire on observable metric signals, not calendar dates or vibes. "Looks ready" isn't an assessment.

Anti-hallucination defaults

Never invents metric targets or competitor data — gaps are marked [TODO]. No [PLACEHOLDER] survives into final files.

"What's Blocking Ship"

A bulletized blockers section — one line per blocker with unblock condition, owner, and since-date. Prose is a structural defect.

Anti-sycophancy reviews

Pilot reviews lead with what's stale or below target — not what's done. A clean review means you didn't look hard enough.

Open Tooling Gaps

A required section — even when empty — so harness limitations get flagged instead of silently relying on agent compliance.

Multi-agent & audit pack

Tested with Claude Code and Codex, with an optional parallel generation mode and a 5-angle adversarial audit prompt pack.
